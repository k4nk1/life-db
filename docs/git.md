# Git 運用方法

## ブランチ戦略

| ブランチ | 用途 | 例 |
|---|---|---|
| `main` | 安定版。機能が完成しテスト済みのコードをマージする | - |
| `feature/<機能名>` | 新機能の開発 | `feature/daily`, `feature/tasks` |
| `fix/<内容>` | バグ修正 | `fix/task-sort-order` |

- `feature` ブランチは `main` から切り、完了後に `main` へマージする
- `fix` ブランチも同様

## コミットメッセージ

```
<種別>: <要約>
```

### 種別

| 種別 | 用途 |
|---|---|
| `feat` | 新機能追加 |
| `fix` | バグ修正 |
| `docs` | ドキュメントのみの変更 |
| `refactor` | 動作を変えないコード変更 |
| `test` | テストの追加・修正 |
| `chore` | ビルド設定、依存関係などの雑務 |

### 例
```
feat: タスク一覧のソート機能を追加
fix: 期限のデフォルト時刻が反映されない問題を修正
docs: API仕様にやること画面のエンドポイントを追加
```

- 日本語で記述する
- 1行で完結させる（本文は不要）
