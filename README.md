## 実装の進捗

実装順序: デイリー → やること → 事実＆思考 → やらないこと → 文書管理 → 資産 → ホーム

各機能: バックエンド → フロントエンドの順で実装。すべて未着手。

## 役割分担

- **Claude**: 全体設計（テーブル定義、API仕様、ディレクトリ構成など）
- **Gemini**: 各機能の実装、バグ修正

## 設計時の主要な決定事項

- TypeScriptでフロントエンド・バックエンドを統一し、shared/typesで型を共有
- テーブルはTanStack Table + MUIコンポーネントで描画（MUI DataGridの有料機能を回避）
- レスポンシブ対応: PC=テーブル表示、スマホ=カード表示に切り替え
- タイムラインのドラッグ操作は実装時にライブラリを調査し、なければ後回し
- 文書管理のデータはDB内にテキストとして格納（ファイルシステムは使わない）
- やらないことの削除は論理削除（削除日時を記録し、過去の週では表示される）
- テストはロジック（分岐）ごとに正常系1件のみ。異常系テスト不要
- フールプルーフ・例外処理は最小限（個人利用のため）
